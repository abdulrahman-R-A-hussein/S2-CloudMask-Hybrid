# Code and claims audit, 2026-11-07

**Scope:** every file in the repo at commit `1bd472d` (v1.0.2):
- `S2_CloudMask_SCIENTIFIC.js`
- `README.md`
- `docs/USAGE.md`
- `examples/custom_area_template.js`
- `CITATION.cff`

Also the public records: GitHub, Zenodo, and the author's website entry.

**Method:** read-only review against the code and the literature in
[`LITERATURE_REVIEW.md`](LITERATURE_REVIEW.md). **The script was not re-run in GEE** during this
audit, because GEE is not reachable from this session. Findings that need a GEE run are marked
**"verify in GEE"**.

**Severity:**
- **High**: wrong for the stated purpose (water quality) or a published claim that is false.
- **Medium**: misleading or fragile.
- **Low**: cleanup.

**Status values:**
- `open → ROADMAP <id>`: not fixed yet; the roadmap item will fix it.
- `fixed (docs) 2026-11-07`: the text was corrected in this session.
- `logged`: outside this repo.

Line numbers refer to `S2_CloudMask_SCIENTIFIC.js` (written `js:N`) unless another file is named.
**The script was not changed in this session**, so `js:` line numbers stay valid until Phase B.

## Part 1: code findings (F)

| ID | Sev. | Finding | Evidence | Consequence | Status |

| F-01 | Medium | **`MIN_AGREEMENT` is defined but never used, and no weighting exists**, yet the code header and the UI call the method "weighted pixel-union" | `js:35` (defined, never read); `js:5`, `js:312` ("weighted"); `js:159` (plain OR) | The documented k-of-n "consensus" mode does not exist. | F-02 | Medium | **The confidence score counts correlated votes.** `cs` and `cs_cdf` are two outputs of the same Cloud Score+ model, yet each counts as one of 4 votes. Shadows are not counted. The map layer takes `.max()` over dates, so it shows the highest agreement on *any* date, not per image | `js:169`, `js:222`, `js:247–248` | "4 = all methods agree" overstates independence; the map mixes dates | open → ROADMAP B1 |
| F-03 | **High** | **Shadow projection never fires over water.** The dark-pixel test multiplies by `SCL != 6`, a design inherited from the GEE tutorial for land | `js:127–130` | The tool targets lagoon water quality, yet cloud shadows *on the water* are caught only if SCL class 3 or Cloud Score+ flags them. The UI and README imply that method 5 covers them | open → ROADMAP D1 (documented in README/USAGE 2026-11-07) |
| F-04 | Low | **Fixed 1 km shadow search at 100 m resolution.** It ignores solar zenith and cloud height, uses a coarse grid, and does not credit the source tutorial | `js:133–141` | Long shadows (low sun, high cloud) are missed. Shadow edges are blocky (100 m) | credit fixed (docs) 2026-11-07; method open → ROADMAP D1 |
| F-05 | Medium | **The morphology may depend on scale, and it erodes before buffering.** `focal_min(20 m)` → `focal_max(50 m)` has no fixed `reproject`, and GEE evaluates focal operations at the requested output scale. The tutorial reprojects to 20 m | `js:172–175` | The mask may differ between map zoom levels and between export scales (**verify in GEE**). Eroding first deletes clouds narrower than about 40 m and thin edges *before* the buffer is applied, which works against the "maximize recall" goal | open → ROADMAP B2 |
| F-06 | Medium | **The "validation" is tautological.** It counts remaining pixels in each composite at 100 m. A union of masks must leave the fewest pixels, so "HYBRID FINAL should have lowest pixel count" is true by construction. `pixelCount()` is never called, and the eight `reduceRegion` blocks repeat each other | `js:265–297`, `js:267–275`, `js:295` | The pixel counts measure yield, not accuracy. No accuracy has ever been measured (see C-10, C-11) | open → ROADMAP B5, C1–C3 |
| F-07 | Medium | **Inputs fail silently.** `CLOUDY_PIXEL_PERCENTAGE < 60` can drop a requested date without warning. Only the total count is printed. An image with no s2cloudless match makes `ee.Image(img.get('s2cloudless'))` fail, and one with no Cloud Score+ match is masked | `js:59`, `js:73–80`, `js:82`, `js:100` | A user can believe 3 dates went into the composite when only 1–2 did | open → ROADMAP B3 |
| F-08 | Low | **The UI depends on hard-coded layer indices** (0–7 results, 8–14 overlays) | `js:320–325`, `js:351–369` | Adding or reordering one `Map.addLayer` breaks every button | open → ROADMAP B6 |
| F-09 | Medium | **The template is not runnable.** It tells the user to paste the mask functions in by hand, and steps 8–9 are commented out | `examples/custom_area_template.js:147–177` (line numbers after the 2026-11-07 comment edit) | Copies drift from the main script. There is no shared module | open → ROADMAP B4 |
| F-10 | Low | **The "Final HYBRID mask" layer and the USAGE export of `aggHybridSmooth` are the union over all dates** (`.max()`), not the mask that was applied to any single image | `js:221`, `js:244`; `docs/USAGE.md` export section | A reader may take it as "the mask". It is "cloudy on at least one date" | fixed (docs) 2026-11-07 (USAGE note); code open → ROADMAP B5 |
| F-11 | Low | **No version string or provenance in the output.** The console does not print the script version or the image IDs used | whole script | A result cannot be traced back to a release or to its inputs | open → ROADMAP B7 |
| F-12 | Medium | **The real net buffer is about 30 m, not 50 m.** Eroding 20 m and then dilating 50 m shrinks every detection by 2 px before growing it by 5 px, so the mask extends only about 3 px (30 m) beyond the original cloud edge, and clouds narrower than about 40 m disappear | `js:172–175`; unit test `python/tests/test_metrics_detectors.py::test_morphology_erodes_small_clouds_then_buffers` (found 2026-11-07) | README and USAGE describe a 50 m buffer | open → ROADMAP B2 |
